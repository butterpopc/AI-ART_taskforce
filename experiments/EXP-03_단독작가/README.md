# EXP-03 단독 작가 비교 (작가 1명씩)

- 제안: 사용자 (2026-10-28) — "섞으니 이 작가가 무슨 그림체인지 모르겠다. 1명만 따로 뽑는 버전도 필요"
- 설계: 컨트롤 타워 · 상태: **진행 중 (2026-10-29~)** — 아래 "실제 진행" 참고
- 관계: EXP-02 무작위 200조합 순위는 완료([결과 1](../EXP-02_StyleLab/RESULT_1_무작위200.md)). 이 실험 결과로 작가를 추린 뒤 조합 단계로 돌아간다

## 실제 진행 (2026-10-29, 계획에서 바뀐 점)

- **작가 수**: 214명 → **4,665명** (pool1 214명 + [작가 풀 2](../EXP-02_StyleLab/README.md) 4,451명). 사용자 목적: 작가 그림체를 몰라서 "NovelAI가 각 태그를 어떻게 그리는지"를 넓게 본다
- **폴더**: 별도 폴더가 아니라 **집 PC 서버의 기존 데이터 폴더**에서 진행(폰으로 원격 생성). 단독 조합은 작가 1명이라 기존 조합과 구분된다
- **생성 속도(실측, 사용자 보고)**: 한 장 약 4초 → 200장 약 15분, 전체 약 5~6시간
- **거르는 방법**: 삭제하지 않는다. 삭제하면 그 작가가 다시 뽑힐 수 있다(코드 확인: 중복 검사는 남아 있는 조합만 본다). 대신 갤러리에서 여러 장 골라 **"Elo 수정"**으로
  - 싫어요 = **Elo 0**, 좋아요 = **Elo 20000**
  - 효과: 목록에 남아서 같은 작가가 다시 안 뽑히고, 점수가 정해진 걸로 처리돼서 대결 배치에서 빠진다
- **사용자 점수 기준 (2026-11-01 사용자 정의)**: Elo로 표시한다. **100000 = 최애**(아직 없음. sakimori_(hououbds)의 100000은 입력 오타 — 원래 0(싫다)을 주려다 기본값 10000 뒤에 0이 붙음) · **50000 = 확 끌림**(제안, 추리기 편하게) · **20000 = 꽤 괜찮음** · **500 = 별로인데 애매** · **0~24 = 싫다**. 표시 안 함 = **봤지만 눈에 안 띄었거나 별로라 넘긴 것**(사용자 설명, 11-01) 또는 아직 안 본 것. 둘을 구분하려면 어디까지 봤는지(정렬 순서·멈춘 위치)를 함께 기록한다
- **11-01 오전 진행 (실측)**: 4,519장 중 약 256장 표시 — 괜찮음 113(+오타 1),  애매 11, 싫다 125
- **회사에서**: 생성 버튼만 누른다. 그림이 뜨는 화면(대결, 그림체 목록 등)은 열지 않는다
- **판별**: 오늘 밤 손으로 600장 먼저 → 할 만하면 계속, 지치면 자동 정렬 도구([R-005](../../research/R-005_그림판별자동화.md), 보류 중)
- **2026-10-31 초기화**: 사용자가 초기화 버튼을 시험하다 그림을 모두 지움. 그 직전 상태(조합 3,353개, 대결 2,641번)는 사용자가 9시 39분에 보낸 state.json 사본으로 남아 있음(컨트롤 타워 보관, 사용자에게도 전달). 사용자는 **처음부터 가중치 1.0으로 4,665명을 다시 뽑기로** 함. 초기화 전 대결로 자리 잡은 단독 작가 순위(검증 안 된 참고용): [placed_singles_1031.csv](placed_singles_1031.csv). 교훈: 큰 작업 전 `data/state.json`을 복사해 두기
- **끝나면**: 좋아요 30~50명 → 그 작가끼리 2명 조합(가중치 1.0) → 다른 시드로 확인

## 왜 필요한가

조합 대결에서는 어떤 작가 덕분에 이겼는지 알 수 없다. 도구의 "작가 점수"가 그걸 계산하지만, 작가 1명당 등장 횟수가 적으면(214명·조합 200개 기준 약 3~4회, 계산) 0 근처에 머문다 (도구 README). 1명씩 따로 보면 **작가별 그림체를 직접 확인**할 수 있다.

## 진행 방법 (3단계)

| 단계 | 하는 일 | 예상 수고 |
|---|---|---|
| 1. 생성 | 214명을 1명씩 1장 생성 | 클릭 몇 번. 무료 (V4.5 Full) |
| 2. 갤러리 거르기 | 그림체 목록에서 훑어보고 **확실히 아닌 것만 삭제**. 30~50명 남기기 | 15~30분 (추정) |
| 3. 대결 | 남은 30~50명만 블라인드 대결 → 순위 | 약 150~350번 선택 (계산: 1명당 5~7번) |

→ 214명 전부를 대결로 배치하면 약 1,500번 선택이 필요하다 (계산). 2단계 거르기가 수고를 크게 줄인다.

## 도구 설정 (별도 폴더 권장)

- **도구 폴더를 하나 더 만든다** (zip을 다른 폴더에 한 번 더 풀기, 예: `NAI-Style-Lab-단독`). 도구는 폴더마다 데이터를 따로 저장하고, "이미 실행 중" 확인도 데이터 폴더 기준이다 (코드 확인: main.py). → 기존 EXP-02 진행분(조합 200개 중 60개 배치)이 그대로 보존된다
- 새 폴더에서 API 키를 다시 입력 (키는 `data/`에 평문 저장 — 공유 금지)
- 프롬프트·네거티브·시드·모델: **[P-003](../../prompts/P-003_StyleLab_실험환경.md)과 동일** (EXP-02와 비교 가능하게)
- 작가: [pool1_user.txt](../EXP-02_StyleLab/pool1_user.txt) 214명 붙여넣기, 기본 작가 23명 삭제
- 조합 규칙: **조합당 작가 최소 1 · 최대 1**, **가중치 최소 1.0 · 최대 1.0** (작가마다 같은 세기)
- 무작위 조합 개수: 200 → 생성. 도구는 이미 만든 조합을 피해서 뽑는데, 30번 시도해도 새 조합이 안 나오면 "만든 만큼으로 마칩니다"라며 멈춘다 (코드 확인). **멈추면 한 번 더 생성**을 눌러 남은 작가를 채운다
  - 가중치를 1.0~1.0으로 못 넣게 막으면 0.99~1.0으로 (추정)
